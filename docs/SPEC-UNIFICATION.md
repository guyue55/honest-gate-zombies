## 5. 备注：架构师 A-10 公式为何不选

A-10 的 `screenY=256.2+529.5·z^2.2` 在 z=1 时只到 785.7，且 `scale(0)=0.18`、`halfWidth(0)=28`，远处压缩更激进，视觉纵深更强；但它与已下发的实现 spec 与 QA 断言基线不同，切换成本高、收益边际，且 `z^2.2` 在低端设备上每帧多一次 `Math.pow`。`RENDERING.md` 的 `z^1.6` + 线性 halfWidth 已能形成明确的近宽远窄，且计算更省。**这不是技术优劣之争，是执行一致性裁决。**

未来若要做视觉调优，统一在 `game-render` 局部改这一个函数即可，不影响 core、关卡、状态机与测试断言——这正是渲染抽象层（RENDERING §5 / U-2）的价值。
