## 二、视觉识别结论（跨 5 款游戏高度一致）

### 2.1 色彩与明度
- **明亮、高饱和、干净**：跑道是白色/浅灰/中灰柏油，天空是亮蓝/紫，地面是冰蓝晶体或沙漠黄；**没有一款用深色霓虹夜景**。
- **我蓝 vs 敌红**是功能性对比色（Count Masters 蓝 vs 红、Mob Control 蓝 vs 红、Last War 蓝 vs 红）；Join Clash 用黄 vs 紫。
- 主体是**平涂 + 厚描边 + 明确阴影**，不用细线网格、不用发光细边勾轮廓。

### 2.2 数字门（本作最核心视觉，差距最大）
- Z Route：门是**半透明发光蓝色玻璃板**，边缘有**白色电光/闪电粒子**，门内 `+2` / `+3` / `×2` / `800` 是**超大白色粗体字（深色描边）**；门按等级呈现绿→蓝→金/紫的辉光分级。
- Mob Control：半透明玻璃板按倍率分色（紫 `x4` / `x3`、粉 `x2`、蓝），**超大白色粗体黑描边数字**，穿过时有 `pop` 膨胀与光爆。
- Count Masters：亮青色玻璃板 + 白色粗体 `+50` `×12`，门顶有**关卡进度条与终点格旗**。
- 共性：门有**厚度/立体边框**、内部扫光、穿门瞬间光爆；数字字号占门高 40–60%。

### 2.3 数量感（最核心爽点）
- Count Masters `200 vs 200`：红蓝人群各自**密密麻麻排成方阵铺满跑道宽度**，边缘散落零头，形成「流体」感。
- Last War / Mob Control：红色单位**从近处一直铺到地平线**，一眼望不到头。
- 人群头顶有**大数字气泡**（红底白字 `49` / `200` / `1000`，白字 `59` / `148`）。
- **关键因果**：HUD 数字变大时，画面上的人**真的同步变多**，不是只有数字变。

### 2.4 反馈与演出
- **伤害数字弹字**：Z Route 僵尸身上飘 `-15` `-35`；Mob Control `45` `148`；Last War 木箱大数字 `24`、`800`。
- 穿门/命中：光爆、白色火花、烟尘、放射粒子、屏幕轻微震动。
- 音效（评测描述）：穿门 chime、炮击节奏、塔倒塌声，构成「satisfying」闭环。
- 战斗：蓝色弹幕交叉扫射、尸潮成片倒下、Boss 血条 `998` / `932` 配骷髅图标。

### 2.5 目标感与 HUD
- 顶部**关卡进度条 / Boss 血条**，终点有明确主体（巨型 Boss、城堡、尸潮压城）。
- HUD 极简但字号大：关卡数 `LEVEL 7`、货币胶囊 `499` / `600` / `345`，右上角贴边。
- 商店宣传级**粗体描边大字**（`AGAINST ZOMBIE` / `THINK QUICKLY` / `EPIC BATTLES`）→ 可转化为关卡开始标题卡。

### 2.6 镜头
- 第三人称背后略俯视，跑道自下而上收窄并**占满画面**，地平线在上方 10–20%，远景主体在门之后。

## 四、二次分析确认（用户硬性要求）

> 对第三节每个结论与第五节每项改动，逐条复核「是否成立 / 是否触碰硬约束 / 回归风险」。

### 确认 1：整体明亮化 vs 灰阶可访问性 —— **可行，但必须保留四重编码**
- 现有 QA 有 `grayscale` 断言，正负门在灰阶下靠：① `gatePath` 形状（正门圆角上扬 / 负门折角下压）② 运算符文字（`+ − × ÷`）③ 虚线/实线选中框 ④ 明度差。
- 改配色**不得删除 `gatePath` 的形状分支**，且新门要保留运算符与明度差（正门亮青、负门红紫，灰阶下亮/暗仍可分）。
- 回归风险：中。必须重跑灰阶截图 + 双协议 QA。

### 确认 2：人海铺满跑道 vs 60fps 性能预算 —— **可行，但必须分层批量绘制**
- 现状 `MAX_DRAW_UNITS=120`，`drawUnit` 每个含多段 path + 渐变 + 描边；若逐个画 300+ 必然掉帧（QA 帧率断言 ≥45fps）。
- 方案：**近景精细层**（现有 `drawUnit`，12–40 个）+ **远景人海层**（新增，一次 `beginPath` 批量画 N 个头/身剪影、一次 `fill`，零渐变、零 `shadowBlur`）。绘制调用数不随人数线性增长。
- 数量按画质档位封顶，reduced-motion 再降。回归风险：中，需实测 FPS 与 6 组门满屏场景。

### 确认 3：新增电光/粒子/伤害数字 vs 确定性 —— **可行**
- 现有代码已全面使用 `Core.makeRng(seed)`（种子化 PRNG）与 `frame/index` 派生；新增视觉随机一律沿用，**禁止 `Math.random` 参与生成或胜负**。
- 不新增 Core 导出 API（26 项不变），不引入任何全局随机源。回归风险：低（static-audit U-9 会检）。

### 确认 4：视觉演出 vs 100% 诚实玩法 —— **可行，且必须严守「不新增机制」**
- 胜负在 S3 入口由 `resolveBattle` 快照一次性锁定；所有新增内容只在 `game-render` IIFE 与 `S.effects`（纯装饰），不参与 `applyGate` / `bestPath` / `resolveBattle` / `verifySolvable`。
- **明确排除**：调研中出现的道具、救人质、武器盲盒、金币、升级、SLG、复活、广告 —— 一个都不加。每关仍是「门组预览 → 选门跑酷 → 自动开火 → 结算」。
- 回归风险：低，但需在报告中明确「仅表现层」。

### 确认 5：门样式大改 vs QA 自动化对齐 —— **可行**
- QA 通过 `__GAME_DEBUG__` 的 `activeGroup / currentLane / targetX` 做键盘/点击闭环，不依赖像素；`laneCenterX` 与 `projectX / halfWidth / scaleOf` 保持不变 → 屏幕坐标映射不变。
- 回归风险：低。

### 确认 6：零外链 / 单文件 / `file://` 双击可玩 —— **可行**
- 全部 Canvas 2D 程序化绘制 + Web Audio 合成；参考截图**仅离线学习用，运行时不引用、不打包**。不引图片、字体、脚本、CDN。回归风险：低（`externalRequestCount` 断言）。

### 确认 7：BigInt 无限关卡下「人数密度」映射 —— **可行，需防溢出**
- `powerText` 是 `Core.formatNumber` 产出的字符串，可能极长；**不把 BigInt 直接转 Number**（会 Infinity）。密度用 `Math.min(1, (digits-1)/9)` 或 `unitCount` 已封顶值派生，纯视觉、不影响数值。
- 回归风险：低（core.test 1–1000 关断言覆盖）。

### 确认 8：reduced-motion / 画质档位 —— **可行**
- 新增光爆、电光、粒子、震动一律在 `reducedMotion` 下关闭/减弱；人海层按 `tier` 限数量；`low` 档关闭 `shadowBlur`。回归风险：低（QA 有 reduced-motion 断言）。

### 确认 9：「体验不好」的非视觉成分复核 —— **结论：只补「因果、反馈、目标感」，不补机制**
- 用户要的是「画面变爽」。行业结论一致：爽点 = 决策零门槛 + **数字变大立刻带来画面变化** + 数量碾压 + 即时夸张反馈。
- 因此本轮只做：人群密度随兵力膨胀（因果）、穿门光爆与大数字弹字（反馈）、伤害弹字与尸潮成片倒下（割草）、顶部进度条与远景目标（目标感）、关卡标题卡（仪式感）。
- **二次确认**：这些全部是表现层，**不构成第二玩法**，不违反「每关都是这个玩法」。

## 五、实施方案（全部落在表现层）

1. **整体色调**：`COL` / `themeTop` / `beginFrame` / `drawBackground` / `drawTrack` 改明亮高饱和；删细网格；加立体路缘、路面分段条纹、白色车道虚线、远景城市废墟与尸潮压城剪影；暗角从 0.45 降到 ≤0.12。
2. **门**：半透明发光玻璃板 + 内部扫光 + 粗亮边框 + 确定性电光边 + **超大白色粗体描边数字**；保留 `gatePath` 形状编码与运算符箭头。
3. **人海**：新增远景批量剪影层（我方蓝 / 敌方红），密度随兵力对数增长；新增人群**大数字气泡**。
4. **反馈**：`gateBurst` 光爆 + 人群增殖脉冲；S3 **伤害数字弹字**（`-N`）+ 尸潮成片倒下 + 增强弹幕/火花；穿门 `numberPop` 放大。
5. **目标感 / HUD**：顶部关卡进度条（当前门组/总组数 + 终点旗）、Boss 血条保留并明亮化；HUD 改大字号胶囊卡片；S1 预览改明亮卡片 + 大号「第 N 关」标题卡。
6. **不动**：Core 26 项 API、胜负逻辑、门组/traps 生成、输入映射、`laneCenterX`、投影函数、状态机时序、音频开关逻辑。

## 六、验收标准
- Node 三层全绿（26 项 API / core.test / static-audit 0 硬违规）。
- 真实浏览器 4 关通关全 WIN、`externalRequestCount=0`、`console/pageerror=0`。
- 交付级 `browser_check.py` 双协议 0 失败，含**灰阶可访问性**、**reduced-motion**、**5 视口**、**6 组门满屏 FPS ≥45**。
- 升级前后截图目视对比：明亮度、门数字可读性、人海密度、数字气泡、伤害弹字、进度条均可辨。

## 八、V3 迭代：视觉与体验的第三轮（2026-11-13）

> 用户指令：「重构升级，游戏体验太差，不仅视觉形象、体验都很哈，游戏体验也很差，随便动几下一个关卡就结束了，请充分联网调研专业资料、方案、经验等，全面优化、重构、升级」

### 8.1 结构层：门必须压在队伍之上

旧顺序 `traps → gates → allies` 让近景方阵把门板与地面陷阱各盖掉一半（截图里「门是断的」）。

- 新顺序：**horde → boss → allies → gates → traps**。
- `TEAM_Z` 0.86 → **0.92**（队伍更靠镜头），门 `z = 0.24 + 0.62·prog`，`z > 0.90` 即退出绘制（判定发生在 z≈0.86）。
- 门值按门洞宽度自适应缩字（`maxW = laneW * 0.86`），`+2.76K` / `-1.72K` 不再撑破门板、不再与邻门相撞。

### 8.2 陷阱必须「在门板上」而不是只在地面

地面陷阱在近景会被队伍挡住，体感等于没有。现在凡 `g.trapped` 的门板顶部都画 **黄黑斜纹警示带**，数字下方再叠一个 `!` 三角：
形状（斜纹）+ 颜色（黄黑）+ 符号（`!`）三通道，灰阶下也成立。

### 8.3 人海不再「一分为二」

远景剪影层原本 `spreadU` 过宽且不跟随队伍，截图里队伍左侧出现一团「无主幽灵人」。
现在：我方 `spreadU` 收窄到 **0.26**（敌方 0.72）、`far/near` 收为 **0.50/0.70**、并统一 `uCenter = s.teamU`。
S2 期间尸潮纵深 `hordeSpan` 收窄到 **0.22**（S3 仍 0.62），路面不再「到处是人和怪」。

### 8.4 数字必须读得出来

### 8.5 Boss 从「紫色胶囊」变成「丧尸王」

## 9. V4 · 战斗视觉重构（2026-11-14）

> 触发：「射击效果、子弹效果、碰撞效果、对战效果都很潦草」+「全面检查和审核，逐一处理、测试」。
> 调研依据与参数对照见 `docs/V4-AUDIT.md §0 / §0.1`；验证数据见 `docs/TEST_REPORT.md §14`。

### 9.1 问题定性：不是画得糙，是画的和发生的不是一回事

V3 的 S3 里存在三套互不相干、都按帧随机生成的「战斗特效」：

| 旧实现 | 位置 | 实际效果 |
|---|---|---|
| 每帧 10 条 `{kind:'bullet', x, y, t}` 静态短斜线 | `buildScene()` + `drawEffects()` 的 `moveTo(x,y)→lineTo(x+14,y-26)` | 子弹不移动、不从枪口出发 |
| 每帧 7 个随机爆炸点 | `buildScene()` | 爆炸点与任何一只僵尸无关 |
| 每帧 3–6 条随机「短曳光弹」 | `drawEffects()` 末尾 | 与上一套子弹方向 / 位置无关 |
| 每 5 帧随机 `bullet` / `hit` | `tickS3()` | 第四套随机源 |

再加上 `fire` / `zombie.down` 音效分支定义了却从未被调用、枪口焰常亮、`slowmo` 只叠一层黄色蒙版、
`flash` / `shake` 整个 ttl 恒亮后一帧消失——观感必然是「潦草」。
**结论：局部加粒子 / 调颜色无效，必须把表现层接到真实模拟上。**

### 9.2 三层结构

```
game-session（模拟，确定性）
  spawnVolley() 每 84ms 一拍 → S.bullets[]：枪口(u0,z0) → 某只存活僵尸(u1,z1)
  tickCombat(dt) 推进 t，t>=1 → onImpact(bx)
  onImpact() 单一接触帧入口：flash / knock / dead / 冲击环 / 火花 / 碎屑 / 音效 / 顿帧 / 屏震
        ↓ buildState() 下发 bullets / fireSlots / zombies / effects / combatWin
game-render（只投影，不算逻辑）
  drawCombat(s) 非线性推进 1-(1-p)^1.45、taperPath 锥形曳光、出生渐显
  drawHorde(s) 逐只闪白 / 击退 squash / 520ms 溶解 / 尸体留痕
  drawEffects(s) muzzle / impact / debris 三类接触帧特效
game-audio（节流）
  fire / bullet.hit / boss.hit / zombie.down
```

### 9.3 视觉参数与动态范围

| 元素 | 普通命中 | 重击 | Boss |
|---|---|---|---|
| 闪白 | 80ms 纯白剪影 + 黄边 | 同 | 同 + 整体抖动 |
| 火花 | 8 粒 / 200ms | 10 粒 / 260ms | 14 粒 / 300ms |

| 击倒 | 520ms 溶解 + 低透明度尸体留痕 | + 8 粒碎屑 | 同上 |

| 屏震 | 无 | 5px | 8px |
| 冷却 | — | `hitstopCooldown=620ms` | 同 |
