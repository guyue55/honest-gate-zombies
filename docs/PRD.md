## 0. 一句话产品定位

> **一款每一关都是广告里那个玩法的网页游戏：选数字门 → 兵力增减 → 自动开火清僵尸 → 结算进下一关。没有隐藏玩法，没有骗人广告。**

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

| # | 目标 | 衡量口径 |
|---|---|---|
| **G-1 诚实性** | 从第 1 关到无限关，每一关都是同一套「数字门 → 兵力 → 清僵尸 → 结算」循环，绝不跳转到任何其他玩法 | 对任意关卡 N，玩法状态机阶段序列完全一致；代码中不存在其他玩法入口、广告位、外链跳转、局外系统 |
| **G-2 可达性** | 零门槛、零成本、零依赖地玩到：不安装、不联网、不登录、不看广告、不付费 | `file://` 双击可玩、断网可玩、运行时网络请求数 = 0、无登录/内购/广告 SDK |
| **G-3 可持续可玩** | 无限关卡、难度成长但绝无死局，单局 20–60 秒，随时可退出、随时可回来 | 生成器产出 1000 关全部通过可解性校验；任意关卡存在至少一条必胜路径；失败可免费无限重试 |

### 2.2 目标用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| **被「货不对板」广告坑过的轻度玩家**（首要） | 刷到「+1 ×2 打僵尸」广告点进去，发现是 SLG 后秒退；在朋友圈/微信群吐槽 | 「我就想玩广告里那个，别给我整别的」 |
| **碎片时间摸鱼者** | 地铁、排队、工作间隙、追剧时单手竖屏；随时要能退出 | 10 秒上手、一局半分钟、单手可玩、不打扰 |
| **被广告复活与卡关劝退的玩家** | 见过「差一点就过关」「看 30 秒广告复活」 | 失败不惩罚、不逼看广告、不制造焦虑 |
| **桌面端偶发玩家 / 分享者** | 电脑浏览器打开链接试玩，或把 GitHub Pages 链接发给朋友 | 鼠标与键盘同样可玩、链接一开就能玩、无需部署后端 |

**非目标用户**：追求长线养成、抽卡、PvP、排行榜竞争的玩家（本产品明确不服务，也不做任何引导）。

### 2.3 核心用户故事（8 条）

| # | 用户故事 |
|---|---|
| US-1 | 作为被假广告坑过的玩家，我想打开链接后**第一关就是广告里那个数字门玩法**，这样我不用先看完新手教学或建设基地才知道自己被骗了没有。 |
| US-2 | 作为竖屏单手玩的用户，我想**按住左右滑动把队伍对准 +7 或 ×3 的门**，这样一次决策就能立刻看到兵力数字暴涨。 |
| US-3 | 作为不想动脑太多的用户，我想**队伍自动前进、自动开火**，这样我只需要做「选哪道门」这一个决定就能享受清屏割草的爽感。 |
| US-4 | 作为被「差一点就过关」套路烦透的玩家，我想**失败后直接免费重试本关**，不用看 30 秒广告、不用等、不扣任何东西。 |
| US-5 | 作为连续玩下去的玩家，我想**每 5 关遇到一个血条很厚的 Boss 关**，并且前一关的门组给我足够大的倍率去打它，这样难度在涨但我永远有解法。 |
| US-6 | 作为在地铁里断网的用户，我想**整局游戏完全不联网也能玩**，所有画面和声音都是浏览器自己生成、不加载任何外部图片或字体。 |
| US-7 | 作为用电脑打开的玩家，我想用 **A/D 或方向键、或鼠标拖拽**也能完成同样操作，并且界面在宽屏下不错位。 |
| US-8 | 作为想分享给朋友的用户，我想**把单个 `index.html` 或 GitHub Pages 链接发过去就能玩**，对方不需要 `npm install`、不需要起本地服务器。 |
| US-9 | 作为色觉辨识困难或安静环境里的用户，我想**门除了颜色还带 `+ − × ÷` 符号与箭头、并且能一键静音**，这样我照样能分清好坏门、也不会突然出声。 |
| US-10 | 作为较真的玩家，我想**在界面上直接看到当前兵力、僵尸剩余战力、本关门组预览与运算结果**，这样我能自己心算、确认游戏没有在背后偷偷改数值。 |

## 3. 产品硬约束（铁律，后续所有成员不得违反）

|---|---|

| **H-7 禁止向用户提问** | 所有模糊点由 PM 自行决策，见第 7 节决策清单；开发/测试阶段遇到歧义，以本 PRD 与决策清单为准，团队内部研究解决。 |

## 4. 需求池（Requirements Pool）

> P0 = Must have（必须实现且可验证）；P1 = Should have；P2 = Nice to have。
> 每条 P0 都给出**可验收口径**，QA 可据此写自动化断言。

### 4.1 P0（必须，共 16 条）

| ID | 需求 | 可验收口径（QA 断言） |
|---|---|---|
| **R-01** | **单文件零依赖启动**：`index.html` 内联全部 CSS/JS，双击 `file://` 打开即可进入首页并开始游戏；不需要本地服务器、不需要构建 | 用 `file://` 协议在 Chrome 打开，控制台无报错，点击「开始」能进入第 1 关并完整通关；`performance.getEntriesByType('resource')` 中不存在任何 `http(s)://` 外部资源 |
| **R-02** | **零运行时外部请求**：运行时不发起任何网络请求（无 CDN JS/CSS/字体/图片/音频/接口/统计） | 浏览器 Network 面板过滤后请求数为 0；断网 / 飞行模式下完整玩 10 关无异常；源码中无 `<script src="http...">`、无 `fetch(` / `XMLHttpRequest` 指向外部 URL、无 `@import url(http...)`、无外链 `font-family` 加载 |
| **R-03** | **四段式关卡状态机**：每关固定 `门组预览 → 选门跑酷 → 自动开火战斗 → 结算` 四段，任意关卡 N 的阶段序列一致 | 状态机日志对第 1 / 5 / 50 / 200 关输出相同阶段序列；代码中不存在第二个玩法状态机或跳转到其他界面的分支 |
| **R-04** | **选门操作**：触屏按住左右滑动/拖拽、桌面 `A/D` / `←→` / 鼠标拖拽，三者统一映射为队伍横向目标位置；队伍自动前进 | 三套输入各自独立可完成一次选门并通关；触屏用Pointer Events 实现，桌面键盘与鼠标均可；无「点击射击」按钮 |
| **R-05** | **四则运算门**：每组 2–3 道并排门，类型 `+n / ×n / -n / ÷n`；蓝/青=正增益，红=负增益；除颜色外必须带 `+ − × ÷` 符号与箭头图形；穿过瞬间整队统一生效，兵力向下取整、下限 0 | 门值与运算结果在 HUD 可见且与预期公式一致；`÷2` 对奇数向下取整；纯灰阶/色盲模拟下仍能区分正负门；不存在「部分单位擦到门边缘只吃一半增益」的歧义（见 RESEARCH E6 的坑） |
| **R-06** | **即时反馈**：穿门时兵力数字跳动 + 飘字（`+7` / `×3`）+ 合成音效 + 单位数量视觉变化；大数字用 HUD 表达，屏幕最多绘制约 120 个单位 | 连续 6 组门时帧率 ≥ 45fps（中端移动设备）；兵力 10 万时画面不卡顿、HUD 显示完整真实数值 |
| **R-07** | **自动开火与胜负结算**：队伍自动开火（纯视觉动画），胜负由确定性战力对拼决定；**胜利条件唯一 = 清空本关全部僵尸（含 Boss）**；HUD 实时显示当前兵力与本关敌方剩余战力 | 相同输入（关卡号 + 选门序列）重复运行 100 次结果完全一致；胜利后必定进入下一关；不存在其他胜利/失败触发源 |
| **R-08** | **程序化视觉生成（资源 P0 核心）**：所有图形由 Canvas 2D 绘制（跑道、门、我方小兵、僵尸、Boss、弹幕、粒子、UI 图标），不使用任何外部图片 / SVG 外链 / 图标字体 / 自定义字体；字体使用系统字体栈 | 源码中无 `<img src>`、无 `url(...)` 指向外部、无 `@font-face` 外部 src；删除 `assets/` 目录后游戏功能完全不变 |
| **R-09** | **程序化音效生成（资源 P0 核心）**：所有音效由 Web Audio 实时合成（选门、增益、减益、开火、僵尸倒下、胜利、失败、Boss 出现），首次用户手势中懒初始化 `AudioContext` 并 `resume()`；提供一键静音 | `file://` 下首次点击后有声；切后台再回来仍能出声（处理 suspended）；静音开关生效并持久化；无 `<audio src>` / 无音频文件请求 |
| **R-10** | **外部资源约束（若未来引入）**：任何外部资源必须登记在**清单化 manifest**（URL、类型、版本/哈希、备用源数组、超时），加载按「主源 → 备用源 → 程序化生成兜底」逐级回退；全部失败时自动降级且**不影响任何一关正常游玩** | 以「模拟主源 404 + 备用源超时」注入测试：游戏仍可完整通关，且界面不出现空白/报错/卡死；manifest 可被枚举、可被脚本校验完整性 |
| **R-11** | **资源健康状态可观测（P0 可验收部分）**：暴露只读健康快照 `window.__ASSET_HEALTH__`，包含每个资源的状态 `ok / fallback / degraded / skipped`、当前使用源、失败原因、耗时；页面内提供帮助面板可查看 | QA 可断言：默认（零外部资源）状态下所有条目为 `generated`/`skipped` 且 `externalRequestCount === 0`；注入失败后状态正确变为 `degraded` 且 `gameplayBlocked === false` |
| **R-12** | **失败免费重试**：兵力归零或战力不足即失败，失败后**免费、无限次重试本关**，回滚到「进入本关时的初始兵力快照」，不扣任何东西、不看广告、不等待 | 连续失败 20 次仍可重试且初始兵力一致；页面中不存在「复活」「看广告」「跳过」「续命」等按钮或文案 |
| **R-13** | **无死局硬约束**：① 每组门**至少一道正增益门**；② 关卡生成器产出后必须做**可解性校验**（模拟一条最优路径，若最终兵力 ≤ 敌方战力则重新生成/调参）；③ 每关存在至少一条必胜路径 | 脚本生成第 1–1000 关，逐关跑「存在必胜路径」断言，通过率 100%；不存在任何一组全负门；不存在必败关卡 |
| **R-14** | **程序化无限关卡 + 阶段性 Boss**：关卡号 n → 确定性参数函数（同一 n 每次一致，便于复现与测试）；门组数 **V3：`min(30, 20+floor(n/2)+(n%5===0?3:0))`**（旧 `2 + floor(n/3)`，上限 6）；每 5 关为 Boss 关，Boss 有独立血条与更高战力，且前一关/本关门组提供解法级倍率 | 第 1–1000 关参数可复现（同 n 两次生成完全相同）；第 5/10/15… 关均为 Boss 关；Boss 关可解性校验同样通过 |
| **R-15** | **诚实性禁止项**：不得出现广告位、看广告复活、登录、内购、礼包码、抽卡、局外基地/养成/科技树、外链跳转、"差一点就过关"式伪随机操控、隐藏数值上限 | 源码全文检索上述关键词无命中（除首页诚实声明文案）；UI 全流程截图逐屏检查无上述元素；首页仅一句事实陈述式诚实文案，不说教 |
| **R-16** | **响应式与可访问性**：竖屏为主适配 320–430px 宽手机；宽屏居中不溢出；键盘可达；对比度 ≥ 4.5:1；`prefers-reduced-motion` 下降低动效；提供静音与重开按钮 | 320 / 375 / 430 / 1280 / 1920 五种视口下无横向滚动、无元素重叠；仅键盘可完整通关一关 |

### 4.2 P1（应当，共 7 条）

## 5. 核心玩法规则说明（可直接作为开发规格）

### 5.1 关卡结构（一关 = 一次完整循环，四段）

| 段 | 名称 | 内容 | 时长目标 |
|---|---|---|---|
| S1 | **门组预览** | 显示关卡号、当前兵力、本关敌方战力、本关全部 2–6 组门的缩略排布；玩家可提前规划 | ≤ 2s，可跳过 |
| S2 | **选门跑酷** | 队伍自下而上自动推进；门组依次进入判定区；玩家左右滑动把队伍对准目标门；穿过即整队统一执行运算；每组结算后立即刷新 HUD 与飘字 | **V3：30–40s**（旧 8–25s） |
| S3 | **自动开火战斗** | 跑道尽头僵尸潮压来；队伍自动开火（弹幕/射线/命中粒子纯视觉）；敌方战力按确定性公式递减；Boss 关显示独立血条；**V3：战斗中可拖拽集火，命中率只影响评级不影响胜负** | **V3：9.5s / Boss 13s**（旧 5–20s 演出） |
| S4 | **结算** | 胜利：显示本关增兵、剩余兵力、连胜/最高关 → 进入第 N+1 关；失败：显示「再来一次，不看广告」→ 免费重试本关 | ≤ 3s |

**状态机约束**：S1→S2→S3→S4→(S1 of N+1)。**不允许任何分支跳到别的界面或玩法**（H-1 / R-03）。

### 5.2 门运算规则

- 门类型与公式（`P` = 当前兵力，结果向下取整，下限 0）：
  - `+n` → `P = P + n`
  - `×n` → `P = P × n`（n 为 ≥2 整数）
  - `-n` → `P = max(0, P - n)`
  - `÷n` → `P = floor(P / n)`（n 为 ≥2 整数）
- **每组 2–3 道门并排**，必含 ≥1 道正增益门（`+n` 或 `×n`）；负门不得同时为高倍率除门与高值减门的组合。
- 门值随关卡 n 与当前兵力区间动态配平，落实「小队伍加法更优、大队伍乘法更优」：当 `P < 20` 时正门以 `+n` 为主并配 1 道 `×2`；当 `P ≥ 20` 时至少提供 1 道 `×2/×3`，保证乘法的期望收益高于加法。
- 判定方式：**离散事件**。以队伍中心横向坐标落在哪道门的区间为准，整队统一生效一次，不做部分单位命中（避免 RESEARCH E6 的边缘歧义）。
- 门值、运算结果、当前兵力全程在 HUD 可见；不做后台暗改、不做隐藏上限（H-8）。
- **属性增益门（如「攻击 +47%」）不纳入 P0**：它会把「兵力」这一个清晰变量变成多变量系统，破坏可验证性与可心算性。统一只用四则兵力门。

### 5.3 战斗结算（确定性、可断言、无死局）

```
进入 S3 时：我方兵力 P，敌方战力 Z（= 僵尸数量 × 单体强度，Boss 关另加 Boss 血条）
逐帧可视化：每秒我方造成 P × k 的伤害 → Z 递减；
            同时敌方每秒削减我方 d 点兵力 → P 递减（用于表演消耗战，1:1 抵消的视觉化）
终局判定（确定性）：
  若进入 S3 时 P ≥ Z  → 胜利，剩余兵力 = max(1, P - floor(Z × lossRatio))
  若进入 S3 时 P <  Z  → 失败，回滚到入关兵力快照，免费重试
```

- `k / d / lossRatio` 为固定常量，随 n 不暗改；**胜负由进入 S3 时的 `P ≥ Z` 唯一决定**，逐帧动画只做表现，不改变结果 —— 这样 QA 可以纯函数断言，也彻底杜绝「差一点就过关」的伪随机操控。
- HUD 在 S3 前就显示 `P` 与 `Z`，玩家可自行心算是否需要回去重选门（R-10 / H-8）。
- **胜利条件唯一：清空本关全部僵尸（含 Boss）**。无「占领基地」「倒计时生存」「护送」等第二胜利条件。

### 5.4 胜负条件与失败处理

| 结果 | 条件 | 处理 |
|---|---|---|
| **胜利** | `P ≥ Z` 且僵尸全部清空 | 结算 → 自动/点击进入第 N+1 关；记录最高关（R-18） |
| **失败** | `P < Z` 或兵力归零 | 显示「再来一次，不看广告」→ **免费、无限次重试本关**，回滚到入关兵力快照；不扣任何东西、不弹广告、不等待、不降级难度 |

> 明确禁止：看广告复活、看广告赢道具、看广告跳关、失败后削弱关卡、连败补偿、限时礼包、复活卡。

### 5.5 难度曲线

| 参数 | 规则 |
|---|---|
| 门组数 | **V3**：`min(30, 20 + floor(n/2) + (n%5===0 ? 3 : 0))`（旧值 `min(6, 2 + floor(n/3))`） |
| 敌方战力 `Z(n)` | 分段线性增长：每关约 +12%~18%，每 5 关（Boss 关）额外跃升 |
| 正门量级 | 与 `Z(n)` 同步放大，保证「选对门」的路径始终能压过 `Z(n)`；大倍率门优先放在路径前段（可被后续再乘一次，RESEARCH E5） |
| 负门量级 | 随 n 温和增长，但**永不超过当前最优正门收益**，避免「选错一次直接死」的劝退感 |
| Boss 关 | `n % 5 === 0`：僵尸战力显著提高、Boss 独立血条与专属出现音效；**本关及前一关的门组必须提供解法级倍率**（可解性校验强制检查） |
| 里程碑 | 10 / 20 / 50 / 100 关仅更换配色与称号（R-20） |

**可解性校验（R-13，硬性）**：生成器产出关卡后，模拟「每组选收益最大的正门」得到 `P_best`，要求 `P_best > Z(n)` 且留 ≥10% 余量；不满足则重新生成或调整门值。同时验证每组至少一道正门。QA 脚本对第 1–1000 关逐关断言，通过率必须 100%。

### 5.6 关卡数量 / 无限关卡策略

- **程序化无限关卡，不设终点、不设「通关」结局**。理由：无需内容制作、可无限玩、可脚本化校验、不存在「最后一关之后没东西」的落差。
- 关卡号 n → **确定性参数函数**（同一 n 每次生成完全一致），便于复现、调试、QA 自动化（R-14）。
- 不使用随机数种子漂移，不按玩家表现动态暗改难度（H-8）；玩家表现只影响当前兵力，不影响关卡生成。
- 第 1 关即**正式关卡**（有完整四段、有真实僵尸、有胜负），不设独立教学关、不做「第一关闭眼过、第二关地狱难度」的套路（RESEARCH C1/C2 的反面）。操作教学仅为一行浮动提示（R-21）。

| **D-05** | 战斗是真实物理弹道还是确定性结算 | **确定性战力对拼（`P ≥ Z` 唯一判胜）+ 自动开火的逐帧可视化动画** | 可复现、可被 QA 纯函数断言、可心算（H-8）、彻底避免「差一点就过关」的伪随机操控，也更容易保证无死局。 |
| **D-06** | 失败怎么处理 | **免费无限重试本关，回滚到入关兵力快照；不削弱难度、不补偿、不弹任何东西** | 诚实铁律 H-1；直接对冲行业「看 30 秒广告复活」（RESEARCH C4/C5）与「差一点就过关」（C2/C4）。 |
| **D-07** | 如何保证无死局 | **① 每组至少一道正增益门；② 生成器强制可解性校验（最优路径 `P_best > Z` 且留 10% 余量），不过则重生成** | 把「不可出现死局」从口号变成可脚本验收的硬约束（R-13）。 |
| **D-08** | 兵力显示上限 | **屏幕最多绘制约 120 个单位，超出由 HUD 大数字表达真实值** | DataEye 明确记录同类产品「多怪物同屏 + 特效叠加」会卡顿闪屏（RESEARCH C7）；数量感靠数字与密度阵型即可传达。 |
| **D-09** | 门类型范围 | **P0 只用四则兵力门 `+n / ×n / -n / ÷n`；不做属性增益门（攻击 +47%）、不做多变量系统** | 保持「兵力」单一变量，玩家可心算、QA 可断言、无隐藏数值（H-8）；属性门会破坏可验证性。 |
| **D-10** | 门编码方式 | **蓝青=正 / 红=负 + `+ − × ÷` 符号 + 箭头 + 门框形状，四重编码** | 还原考据语义（RESEARCH E2/C17）同时满足色盲可辨（R-05）。 |
| **D-11** | 是否做局外养成 / 基地 / 英雄 / 抽卡 / 礼包码 | **全部不做** | 用户要的正是「每一关都是广告里那个玩法」；所有现存「半真」产品都是在前 2–3 关后转入这些系统（RESEARCH C7/C10/C12/C13）。 |
| **D-12** | 是否做独立教学关 / 冗长引导 | **不做；第 1 关即正式关卡，仅一行浮动提示教滑动** | DataEye 指出「摒弃新手教学、开局直接上数字门」是正面做法（C7）；同时拒绝「第一关闭眼过、第二关地狱难度」的套路（C1/C2）。 |
| **D-13** | 资源策略 | **P0 完全不使用任何外部资源**（Canvas 绘制 + Web Audio 合成 + 系统字体栈），运行时请求数 = 0 | 一次性解决 CDN 失效、防盗链、混合内容、字体 CORS、`file://` 拦截、缓存不失效、GitHub Pages 子路径七大坑（RESEARCH 第七节）。 |
| **D-14** | 「动态获取和更新机制」如何落地而不违反零依赖 | **定为 P1 且默认关闭**：manifest 清单化 + 可选远程清单 URL + 主源/备用源回退 + 程序化兜底 + 健康快照；**P0 必须能完全离线自洽** | 用户要求「设计一套能动态获取和更新的机制」，但远程清单本身就是外部请求，与 H-2 冲突。以「默认关闭、显式启用、启用后仍不阻断游玩」调和两者，并把清单化/回退/降级/可观测做成 P0 可验收约束（R-10/R-11）。 |
| **D-15** | 文案基调 | **自豪但不说教：首页一句事实陈述「没有隐藏玩法，没有骗人广告」；不攻击同行、不写行业黑幕长文、不用「骗子/割韭菜」** | 用户明确「可以自豪地强调，但不要做成说教」；行业「打假自证」素材虽有效（RESEARCH C11），但那是广告冲突话术，不适合做产品内常驻文案。 |
| **D-16** | UI 语言 / 项目名 | **仅简体中文；项目名 `honest_gate_zombies`（snake_case）** | 与用户语言一致；符合项目命名规范。 |
| **D-17** | 快捷键映射 | **`A/D`、`←/→`、鼠标拖拽三套并存；空格/回车确认按钮** | 满足 H-3 桌面可玩，且不增加任何新玩法维度。 |
| **D-18** | 音效 | **Web Audio 合成，首次用户手势中初始化，默认开启、可静音、偏好持久化** | 规避自动播放策略与 `file://` 音频加载失败（RESEARCH C20/C21）。 |
| **D-19** | 进度存档 | **仅存最高关与静音偏好，`try/catch` 降级为内存态** | `file://` 下部分浏览器限制 `localStorage`；降级不得影响游玩。 |
| **D-20** | 是否做竞品象限图 / 完整竞品分析 | **不做** | 交付总监明确要求「简单 PRD，默认用简单版，不要做竞品象限图那种完整版」；竞品考据已完整落在 `docs/RESEARCH.md` 第五节。 |
| **D-21** | 装饰性障碍（锯片/摆锤/尖刺） | **降为 P2，且即使实现也只做纯背景动画、不参与数值判定** | 考据中障碍会「削掉队伍外缘」（RESEARCH E2/E3），会引入与选门无关的第二套判定，破坏确定性结算与无死局校验；同时用户要的是纯粹的广告玩法。 |
| **D-22** | `×99` 夸张门值 | **降为 P2 里程碑彩蛋，非常规门值** | 仅见于广告素材统计（RESEARCH C11），属夸张素材而非实机常规值。 |
| **D-23** | 分享 / 排行榜 / 服务器 | **全部不做** | 会引入外链跳转、后端与联网，违反 H-1/H-2/H-4。 |

### 8.2 决策冲突裁决原则

1. **硬约束（第 3 节 H-1~H-8）> 决策清单 > 默认模板/惯例。**
2. 任何新想法若引入「第二个玩法状态机」「第二个胜负条件」「外部请求」「付费/广告/登录」，一律否决。
3. 若团队在实现中发现本 PRD 未覆盖的歧义，**由架构师与工程师团队内部研究决定并在交付说明中记录**，不得向用户提问（H-7）。
