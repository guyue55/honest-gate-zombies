## 一、执行摘要（最有价值的 5 条结论）

1. **用户痛点真实且已成行业共识，不是个人错觉。** 网易明确点名《折螺丝》《无尽冬日》《寻道大千》《向僵尸开炮》「广告里的试玩模式和游戏本身玩法简直是两模两样」，并记载了「玩游戏—失败卡关—看广告复活—误点广告进入另一个小游戏」的死循环；微博文章补充了厂商为规避虚假宣传举报，会在角落藏一个与广告玩法一致的「阉割版试玩」。英文侧 fakeadgames 对 Last War 的档案进一步量化：数字门跑酷仅作为副玩法 "Doomsday" 存在，**占游戏内容不足 5%**。

2. **「数字门」是一套边界清晰、已被验证好玩的完整玩法，完全可以独立成游戏，不需要挂在 SLG 上。** 它是 2021–2022 年 hyper-casual 的独立品类（Count Masters / Mob Control / Join Clash / Crowd City）：单指左右滑动、自动前进、穿过成对数字门改变兵力、人数对撞 1:1 抵消、清怪/攻城/Boss、消灭全部敌人即通关。Count Masters 仅 Google Play 单渠道安装量标注 100,000,000+， Mob Control 为 Voodoo 2021 年产品并有 2023 年 HTML5 版。**我们只需把广告里那 30 秒做成 100% 的游戏本体即可。**

3. **市场已经用真金白银验证了「所见即所得」是有效卖点，甚至演化出专门的「打假自证」素材流派。** AppGrowing 对《向末日开炮》全量素材的统计显示，38% 素材是「数字门数值爽感 +1、x2、x99，人口膨胀与清屏割草」；占比第一的创意类型是「真实还原（打假自证）」，素材高频出现「割韭菜中心」「你们这群骗子」「假广告」，「割韭菜中心」台词环比 +904%。DataEye/腾讯新闻记载该作 2026-07-30 上线，4 天从人气榜第 96 冲到第 1，核心打法是「真实数字门游戏、看到即所玩」。**这就是本项目产品定位的市场依据：诚实本身就是差异化。**

4. **但所有现存「诚实」产品都只在前期诚实，2–3 关后必定把用户导向基地建设 / 英雄抽卡 / 大地图 SLG。** 《向末日开炮》是「数字门解决前 1 小时会不会玩，SLG 解决玩一个月后还留不留」；《无尽火线》在数字门战斗后进入「方舟升至 5 级解锁世界地图」；《Last War》在 HQ Lv.20 后转向策略。**市面上不存在「每一关都是广告里那个玩法」的产品——这正是本项目的空白位。**

5. **纯静态 + 零外链不是妥协，而是对同类产品公开短板的最优解。** DataEye 明确记录《向末日开炮》「在高频闯关、多怪物同屏、技能特效叠加场景下容易出现画面卡顿、帧率波动、闪屏、加载延迟」。而 GitHub Pages / CDN / 防盗链 / 混合内容 / 字体 CORS / `file://` 协议拦截 / 缓存不失效等是静态站点外链的常见坑（见第七节）。**结论：视觉与音效全部程序化生成（Canvas 2D 绘制 + Web Audio 合成），运行时外部请求数为 0，是对稳定性、离线、file://、GitHub Pages 四个目标同时成立的唯一方案。**

## 四、玩法考据：广告里那个「数字门 + 打僵尸」到底是什么

### 4.1 交互骨架（一局之内）

```
竖屏跑道自下而上自动推进（玩家不控制前进）
  → 前方出现一组横向并排的「门」（通常 2 道，偶尔 3 道）
  → 玩家按住左右滑动 / 拖拽，把队伍横移到想穿的那道门前
  → 穿过瞬间执行门上运算，兵力数字跳动 + 飘字 + 音效
  → 重复 2~6 组门
  → 抵达跑道尽头 / 遭遇僵尸潮
  → 队伍自动开火（无需点击射击），兵力决定火力密度
  → 两军对撞 / 尸潮被清空 / 打关底 Boss
  → 消灭全部僵尸 = 通关 → 结算 → 下一关
```

关键：**只有一个自由度（横向位置）**，没有跳跃、没有射击按钮、没有技能释放。这是「10 秒上手、三秒完成一次选择—兑现」的根本原因（C7/C10）。桌面端映射为 `A/D` 或 `←/→` 或鼠标拖拽（E2/E3）。

### 4.2 门的类型、数值与视觉编码

| 维度 | 考据结论 | 来源 |
|---|---|---|
| 运算族 | `+n` / `×n` / `-n` / `÷n` 四则运算门，另有一类属性增益门（如「攻击 +47%」） | C14/C15/C10/E2/E5 |
| 常见值 | 正：`+1 +2 +7 +9 +10 +25 +50 +100 +200`、`×2 ×3 ×5 ×6 ×10`；负：`-2 -50`、`÷2 (/2)`；广告夸张素材用 `×99` / `x99` | C8/C11/C14/E2/E5/E6 |
| 颜色语义 | **蓝/青 = 正增益，红 = 负增益**，跨 Count Masters / Mob Control / Last War 三系产品一致 | E2/E4/E5/C17 |
| 变体 | 移动数字门（左右 oscillate / 斜向漂移）、攻击后才解锁收益的门、载具数字门 | C10/E6 |
| 门序规律 | 「加门减门交替出现」，开局先扫一眼门序再动、规划正数为主的路线；「宁可绕路也别吃负数门」 | C12/E2 |
| 决策心法 | 队伍小时加法更优，队伍大时乘法更优；「当前 100 人优先选 ×2 而非 +50」；优先把最大倍率放在路径前段，因为后面还能再被乘一次 | C14/E2/E5 |
| 部分命中 | 若队伍只擦到门边缘，只有部分单位获得增益（对本项目启示：选门判定应做成「整队统一过一道门」的离散事件，避免歧义） | E6 |

### 4.3 队伍 / 兵力单位

- 火柴人 / stickman / 小兵，**我方蓝色，敌方红色**（E2/E4/E5/C17）。
- 「一个人变十个，十个变一百个」；单位穿过门被**复制**，数量以指数增长（E12/E4）。
- 数量可视化：人数越多，群体 footprint 越宽，逐渐填满跑道宽度（E3）。
- 障碍会「削掉群体外缘」——摆锤、旋转锯片、尖刺、深坑、移动屏障、油桶（barrels）（E2/E3/E7）。
- HUD 常驻显示当前兵力大数字，穿门时飘 `+7` `×3` 并伴随音效（C5/C8 截图中可见 `+1`、`20`、`50`、`EXP` 条）。

### 4.4 跑道、僵尸潮、自动开火、Boss

- 跑道：竖屏单向走廊 / 公路 / 末日废土废墟；视角为俯视或斜俯视（C10/E4/E7）。
- 僵尸潮：密度随关卡递增，「成片压来」，屏幕边缘泛红 + 警报声制造危机（C12/C17/C10）。
- **自动开火**：`Your squad fires automatically as you steer it between enemies, barrels, and upgrade gates`（E7）；Mob Control 是自动开火炮口持续喷射小兵流（E4/E5）。玩家全程不需要点射击。
- **对撞结算**：两群相遇时 1:1 互相抵消，「whoever has more bodies wins the clash and the loser is wiped out」（E4/E5/E3）；E6 描述为 tug-of-war，进水（补充）少于前线损耗就会被推回。
- Boss：关底 Boss / King Stickman / Doom Elite / 装甲巨兽，需足够兵力才能打掉；广告素材常见台词「能不能打打打到关底那个 boss」（C8/E2/E3/C10）。
- 通关：**消灭关卡内所有僵尸即通关**（C12 明确），或压过守军攻下基地 / 城堡（E2/E4）。

### 4.5 胜负判定、失败与关卡递进

- 胜：兵力压过敌方 + 清空僵尸 + 打掉 Boss → 领奖 → 下一关（C12/C9）。
- 败：兵力归零 / 被尸潮淹没 / 走到终点兵力不足 → Game Over（E1 的广告逐帧即「选错门 → 小队缩水 → 僵尸潮 → 全灭 → Game Over」）。
- **失败钩子（本项目要禁止的部分）**：「差一点就过关」→ 30 秒激励视频换复活 / 道具 / 跳过关卡（C4/C5/C2）；「看广告复活 → 误点广告进入另一个小游戏」无限循环（C1）；关闭按钮故意做小又窄（C2）；卡关时把引导指向科技中心 / 英雄升级 / 首充礼包（C17）。
- 关卡递进：100+ 关、难度逐步提升、无尽模式（C14）；每 5 关阶段性台阶 + Boss（C10/E3）；后期「数值通胀」与纯数值碾压是公开短板（C10/C16）。
- 广告钩子：故意选错门让观众「想对着屏幕喊：选乘法门啊！」（E1）；降智操作 + 魔性 BGM 引诱评论互动（C6）。

## 六、「诚实」作为产品定位的市场证据

1. **用户怨气已成可被收编的营销资产**：C11 显示《向末日开炮》占比第一的素材类型是「真实还原（打假自证）」，先自嘲再自证，用「割韭菜中心」「假广告」等冲突台词完成信任重建；C1 记载早已有广告专门打「童叟无欺、玩法一致」旗号。
2. **「所见即所得」被行业研究确认为有效转化策略**：C7 认为它解决了「广告炫酷、实机拉胯」导致的秒退与差评；C9 称「广告炫酷、实机拉胯这种行业通病，在这款游戏上基本不存在」。
3. **开局直接给核心玩法是正面做法**：C7 明确对比「冗长新手引导造成前期流失」与「摒弃新手教学、开局直接上数字门闯关，一秒触达核心乐趣」。
4. **但商业产品无法真正诚实**，因为变现依赖局外系统：C10 一句话概括「数字门解决前 1 小时会不会玩，SLG 解决玩一个月后还留不留」；C4/C2 记录 IAA 依赖 30 秒激励视频与「差一点就过关」。本项目不做变现，因此**可以做到商业产品做不到的完全诚实**——这是结构性优势，不是情怀。
5. **反面清单（明确禁止）**：看广告复活 / 赢道具 / 跳关（C4/C5）、插屏广告（C2）、首充礼包码、月卡免广告、英雄抽卡与升星（C10/C17）、局外基地与资源等待（C7/C13）、关闭按钮做小诱导误触（C2）、「差一点就过关」的伪随机操控（C4）、关卡间广告打断节奏（E3）。

## 七、静态站点资源稳定性考据（给架构师的需求依据）

### 7.1 常见坑（按对项目威胁排序）

| # | 坑 | 表现 | 来源 |
|---|---|---|---|
| 1 | **`file://` 协议拦截** | Chrome 下 `fetch` / XHR 读本地文件被 CORS 策略拦截；本地音频加载失败；部分需安全上下文的 API 行为不一致 | C20/C21、单文件实践资料 |
| 2 | **GitHub Pages 子路径** | 项目站点挂在 `/repository-name/`，硬编码 `/assets/x.png` 直接 404；须用相对路径或正确 base path | E11/C18 |
| 3 | **混合内容** | Pages 强制 HTTPS，页面引入 `http://` 资源被浏览器静默阻止 | C18/C19/E10 |
| 4 | **字体跨域 CORS** | `woff2` 需 `Access-Control-Allow-Origin`；CDN / OSS 常默认关闭 CORS；音频还需 `crossorigin` 属性 + 允许 Range 头 + 正确 MIME，否则「假装加载成功然后彻底沉默」 | C19/C21 |
| 5 | **CDN 失效 / 防盗链 / 地区屏蔽** | unpkg、cdnjs 等在国内网络环境可能被屏蔽；Referer 防盗链返回 403；CDN 版本下线或改路径 | C18/E5（浏览器扩展屏蔽第三方内容导致游戏区空白） |
| 6 | **缓存不失效** | Pages 静态资源约 10 分钟缓存；改完用户仍看旧版本，需 cache-bust 查询参数 / purge CDN | C19/E10/C18 |
| 7 | **Jekyll 吞资源** | 以下划线开头的目录被 Jekyll 忽略，需 `.nojekyll` | E10 |
| 8 | **Web Audio 自动播放策略** | 用户交互前 `AudioContext` 为 `suspended`，直接 `start()` 无声；切后台再回来可能重回 suspended；微信 iOS 需 `WeixinJSBridgeReady` | C20/C21 |
| 9 | **同屏性能** | DataEye 明确记录同类产品「高频闯关、多怪物同屏、技能特效叠加」时卡顿 / 帧率波动 / 闪屏 / 加载延迟 | C7 |

### 7.2 业界做法

- **关键依赖内联 / 打包进项目**，不引未经验证的远程脚本（C18 明确建议「将关键第三方库打包进项目或使用代理服务」）。
- **单文件 HTML 零外部依赖**：CSS / JS / 甚至波表数据内联，只要浏览器能读到这个文件就无需联网（单文件 Web Audio 实践资料）。
- **系统字体栈优先**，`font-display: swap`，自定义字体做子集化（E10）；避开字体 CORS 与跨域整类问题。
- 全 HTTPS / 协议相对 URL；相对路径；root-relative 需配 base path（C19/E11）。
- Cache busting 查询参数、Cloudflare Purge Cache（C19）。
- 多 CDN 回退 + `onerror` 切换备用源；加载超时保护。
- **程序化生成兜底**：Canvas 2D 绘制图形、Web Audio 实时合成音效，零字节外部资源，天然免疫 1–7 全部坑。
- 首次用户手势中懒初始化音频并 `resume()`（C20）。

### 7.3 对本项目的需求依据（可直接转成验收项）

> **结论：P0 采用「零运行时外部请求」策略——所有视觉由 Canvas 2D 程序化绘制、所有音效由 Web Audio 合成、字体使用系统字体栈。运行时网络请求数必须为 0。** 这同时满足：双击 `index.html`（file://）可玩、GitHub Pages 直接发布、断网离线完整可玩、无防盗链 / 混合内容 / 字体 CORS / CDN 失效 / 缓存不失效风险。

若未来确需引入外部资源，必须满足「清单化 + 动态更新 + 多源回退 + 失败降级 + 可观测」五要件（详见 PRD 需求池 R-08 / R-09 / R-10），且**降级后不得影响任何一关的正常游玩**。注意：远程清单本身也是外部请求，故动态更新能力定为 **P1 且默认关闭**，P0 必须能完全离线自洽。

## 九、局限与存疑（诚实记录，供架构师参考）

1. 部分来源为游戏门户 / 下载站 / 自媒体，属产品说明与行业拆解而非学术论文；本报告已通过 ≥3 源交叉验证核心机制，但**具体门值、关卡数、排行榜名次等数值以来源自述口径为准，未做二次核验**。
2. C11 的素材占比为「全量推算」口径（如 38% ≈ 11.5 万条），C10 与 C7 的投放量存在两套不可换算的监测口径，报告中未做跨口径换算。
3. E1 属立场鲜明的档案站，「< 5%」「Lie Score 9/10」为其主观评估，仅作定性参考；但其机制描述与 C17/E7/E9 独立吻合。
4. 《无尽火线》资料更新于 2026-11-02，属较新产品，公开拆解较少，其「消灭全部僵尸即通关」主要依据 C12 产品页与 C13 分析，未获得第二家独立媒体逐条确认，故本项目将其作为**关卡结构参照**而非唯一依据（另有 E2/E4 的攻城 / 基地占领胜利条件互为补充）。
5. 本报告未检索到任何公开资料给出「数字门关卡的数学可解性 / 无死局」设计方法——这是本项目需要自行设计并写入 PRD 的部分（见 PRD「关卡可解性硬约束」）。
